# F1 Service 🏎️ 

Сервис для фанатов формулы 1. Предоставляет актуальную информацию о календаре, гонках, результатах, чемпионатах, пилотах и командах.

## 🏁 О проекте

**Статус:** MVP (Minimum Viable Product)

Backend-приложение на Django с интегрированным Telegram-ботом (aiogram), которое предоставляет пользователю актуальную информацию о Формуле 1. 
Сервис развёрнут в Docker-контейнерах с использованием Nginx, PostgreSQL и Redis.

Проект решает главную задачу болельщика: быстро получать актуальные данные о Формуле 1 — календарь, результаты, чемпионаты и напоминания о старте сессий — прямо в Telegram, без необходимости заходить на сайты.

## ⚙️ Технологии

- Python
- Django + Django-Ninja (REST API)
- Aiogram
- PostgreSQL
- Redis
- Celery
- Docker / Docker Compose
- Nginx
- Gunicorn

## 🛠 Основной функционал

- **Календарь** — полный календарь сезона;
- **Оставшиеся гонки** — только предстоящие этапы;
- **Следующая гонка** — детальное расписание ближайшего Гран-при с учётом часового пояса пользователя;
- **Список пилотов** — все пилоты сезона с номерами;
- **Список команд** — все конструкторы сезона;
- **Результаты** — результаты завершённых сессий (FP1, FP2, FP3, квалификация, спринт, гонка) по выбору пользователя;
- **Чемпионат пилотов** — актуальная турнирная таблица пилотов;
- **Чемпионат команд** — актуальный Кубок конструкторов.

## 🔔 Уведомления (Celery)

**Гибкие напоминания** о старте сессий:
  - Пользователь сам выбирает, о каких сессиях напоминать (FP1, FP2, FP3, SQ, Sprint, Qualifying, Race)
  - Пользователь сам выбирает интервал напоминания (10, 15, 20, 30, 60, 120 минут)
  - Несколько напоминаний на одну сессию (например, за 60 и за 15 минут)

## 💬 Обратная связь

Бот отправляет отзывы в закрытый Telegram-канал. Добавьте бота в канал администратором с правом публикации сообщений и укажите ID канала в `.env.dev` и/или `.env.prod`:

```env
FEEDBACK_CHANNEL_ID=-1001234567890
```

Отзывы публикуются новыми сообщениями от имени бота; имя, username и ID автора к ним не добавляются и в приложении не сохраняются.

## 🗺 Планы по развитию

- **История результатов** — просмотр результатов любых прошедших гран-при;
- **Детальная информация** — возможность получать подробную информацию о трассах, командах, пилотах, сезонах;
- **Тестирование** — unit тесты;
- **Мультиязычность** — перевести интерфейс на несколько популярных языков;
- **Расширенный мониторинг** — отслеживание ошибок и нагрузки.

## 🔐 Админ-панель Django

Доступна по адресу `/admin` после запуска backend-сервера.

- Управление Гран-при (даты, время сессий, указание спринт уикенда)
- Редактирование пилотов и команд
- Редактирование информации о трассах

## Мониторинг доступности

Backend предоставляет внутреннюю проверку `GET /health/`: она проверяет соединение
с PostgreSQL и Redis и отвечает `200`, если обе зависимости доступны, иначе `503`.
Проверка не раскрывает детали ошибок и не заменяет мониторинг вне сервера.

Telegram-бот раз в минуту проверяет доступность Telegram API и backend. Чтобы
получать уведомления даже при остановке сервера, настройте внешний Checkly
Heartbeat Monitor:

1. Создайте Heartbeat Monitor с ожидаемым интервалом 1 минуту и запасом
   (Grace Period) 4 минуты.
2. Скопируйте её Ping URL и добавьте его в `.env.prod` на сервере:

   ```env
   SERVICE_HEARTBEAT_URL=<Checkly Ping URL>
   ```

3. Настройте канал оповещений Checkly. Для Telegram понадобится отдельный
   Telegram-бот для уведомлений, его API-токен и ID чата. Не используйте токен
   основного F1-бота. Не публикуйте ни Ping URL, ни Telegram API-токен.
4. Пересоздайте контейнеры backend и бота, чтобы применить endpoint и настройки:

   ```bash
   docker compose -f docker-compose.prod.yml up -d --build backend bot
   ```

Сигнал отправляется только после успешной проверки Telegram API и backend
(включая PostgreSQL и Redis). Если проверка не проходит, сигнал пропускается;
после истечения Grace Period Checkly пометит проверку как недоступную.
Без `SERVICE_HEARTBEAT_URL` локальные проверки пишутся в журнал бота, но
внешних уведомлений не будет.
